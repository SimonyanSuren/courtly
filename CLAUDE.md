# CLAUDE.md

Guidance for AI coding agents working in this repository. Humans: start with the README.

## Commands

Run from the repository root; each one covers every workspace.

- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run knip`,
  `npm run format:check`
- `docker compose up`: the whole stack from production images (PostgreSQL, migrations, the API on
  127.0.0.1:3000, the web app on http://localhost:8080); `docker compose down -v` also deletes the
  data
- `docker compose up -d --wait postgres`, then `npm run start:dev -w apps/api`: the API with
  reload (copy `apps/api/.env.example` to `apps/api/.env` first)
- Database schema: tables are declared in `apps/api/src/modules/**/*.schema.ts`. After a
  change, `npm run db:generate -w apps/api -- --name <change>` writes the SQL migration to
  `apps/api/migrations/` (review and commit it); `npm run build -w apps/api`, then
  `npm run db:migrate -w apps/api` applies pending migrations.
- API tests import `describe`, `it` and `expect` from `@jest/globals`; HTTP tests live in
  `apps/api/test/` and boot the app with `createTestApp()`, unit tests sit next to the code as
  `*.spec.ts`. `npm test` needs Docker: it starts its own PostgreSQL with Testcontainers.
- Jest's `toEqual` treats any two Temporal objects as equal (they have no own properties): compare
  them as ISO strings.
- CI (`.github/workflows/ci.yaml`) runs format:check, lint, typecheck, knip, build and test, then
  `docker compose up --wait` and a health check, on every push and pull request. Actions are
  pinned to a full commit SHA with the version in a comment: update both together.
- `npm run dev -w apps/web`: the web app on http://localhost:5173 with reload; it proxies `/api` to
  the API on port 3000. Web tests are `*.spec.tsx` next to the code: they import from `vitest`,
  replace `fetch` with `vi.stubGlobal` and render the app's routes with Testing Library.

## Structure

`apps/api/src/platform/` holds technical capabilities (config, database, health, http);
`apps/api/src/modules/` holds business areas. `platform/` never imports `modules/` (lint enforces
it). See DECISIONS.md, entry 8. Fixed value sets are enum-like const objects in a module's
`domain/` (`Role.ADMIN`), and each module's errors are functions in `<module>.errors.ts`
(entry 20). `apps/web/src/` holds the React app, one folder per area (auth, courts, admin).

## Rules

- Show every change as a diff and commit only after the user's OK.
- Dependencies are pinned exactly (`.npmrc`: `save-exact`, `ignore-scripts`). The Node version
  comes from `.nvmrc`.
- Commits follow Conventional Commits; commitlint runs in the `commit-msg` hook.
- Decisions go in [DECISIONS.md](DECISIONS.md): what was chosen, what was rejected, and why.
- Comments explain the non-obvious why. Verify version-sensitive claims against primary sources
  (official docs, registries) instead of memory.
- Comments, docs and commit messages give the requirement or the technical reason itself, never
  an outside document.
- Never push, open pull requests or create remote resources without explicit approval.

## Tracking

Work is tracked with Backlog.md in `backlog/`, through the CLI as described below. Keep tasks
short: why the task exists and testable acceptance criteria. Criteria state each requirement in
full, so a task reads on its own. Add notes only for a decision or verification worth keeping.
Tasks change when the work shows they should: edit them through the CLI, note why when the task is
already in progress, and commit the edit with the code that caused it.
