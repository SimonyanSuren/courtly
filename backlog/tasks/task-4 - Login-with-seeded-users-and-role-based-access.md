## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
There are two roles, User and Admin, and the API itself must enforce what each may do: hiding buttons in the UI is not access control. Users are seeded, so there is no sign-up.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A seeded user logs in with email and password and gets a server-side session: a random token in an httpOnly cookie, stored only as a hash; wrong credentials get 401 without saying which part was wrong
- [x] #2 Passwords are stored only as hashes from a slow, salted password-hashing function
- [x] #3 Every route requires a valid session unless it is explicitly marked public; a missing, unknown or expired session gets 401
- [x] #4 Admin-only routes return 403 to users and user-only routes return 403 to admins, tested over HTTP
- [x] #5 `GET /api/auth/me` returns the current user and role, and logging out ends the session and clears the cookie
- [x] #6 Schema changes are versioned SQL migrations generated from the Drizzle schema and applied with one command, from compiled code so the production image needs no dev tools
- [x] #7 Tests run against a database with every migration applied, and each test starts from known data
- [x] #8 State-changing requests from another origin get 403, so another site cannot act with a user's cookie
- [x] #9 Repeated login attempts from one client are limited and answered with 429
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Migrations: drizzle-kit generates SQL from the modules' schema files into apps/api/migrations; npm run db:migrate applies them from compiled code with Drizzle's migrator. First table: users (uuidv7 id, unique lower-case email, name, role, password hash, created_at).

2. Tests: global setup migrates a template database and clones one database per Jest worker; a helper empties the tables before each test.

3. Password hasher: argon2id from node:crypto with OWASP's parameters, a hash string that names its parameters, and a dummy hash for unknown emails.

4. Sessions: sessions table (SHA-256 of a 32-byte random token, user, expiry); login, logout and me; a global guard that denies by default, with @Public() in platform/http; cookie HttpOnly, SameSite=Lax, Secure over HTTPS; Nest's enableCsrfProtection().

5. Roles: @Roles() and a roles guard; 401 and 403 tested over HTTP with test-only routes.

6. Login rate limit with @nestjs/throttler.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Criteria 1, 3 and 5 changed from a JWT to a server-side session, and 8 and 9 were added: with sessions, logout and role changes take effect at once and there is no signing key to protect. See DECISIONS.md.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Login with server-side sessions: a 32-byte random token in an httpOnly, SameSite=Lax cookie (__Host- over HTTPS), stored only as its SHA-256 hash; argon2id from node:crypto at OWASP's cost, with a dummy check for unknown emails so both mistakes get the same 401. A global guard denies every route without a session unless it is @Public(); a second guard checks @Roles() and fails closed with a logged 500 when a route names no roles. Nest's enableCsrfProtection() answers cross-origin state-changing requests with 403. Login is limited per client address (50) and per email (10) per 15 minutes, with 429 and Retry-After; behind nginx the API trusts one proxy hop. Migrations are SQL generated by drizzle-kit and applied from compiled code; tests use a migrated database per Jest worker, emptied before each test. Verified: test/auth.spec.ts, test/roles.spec.ts, test/login-throttle.spec.ts and password-hasher.spec.ts pass (180 API tests), the login limits and cookie were checked end to end through nginx in Docker, and mutation checks broke the guard order, the role checks, the limits and the CSRF and fixation protections, each caught by a test. Follow-ups: the seed data (TASK-9) provides the ready-made accounts; the counters are in memory, so several API instances would need shared storage.
<!-- SECTION:FINAL_SUMMARY:END -->
